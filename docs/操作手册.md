## 3. 任务 2：键盘操控小车 + 核实话题

**终端 B**（先做第 1 节的两步 source）：

```bash
ros2 run turtlebot3_teleop teleop_keyboard
```

按键：

| 键 | 作用 | 键 | 作用 |
| --- | --- | --- | --- |
| `w` | 前进 | `x` | 后退 |
| `a` | 左转 | `d` | 右转 |
| `s` 或空格 | 急停 | `Ctrl+C` | 退出 |

> 提示：**鼠标要点在终端 B 上**再按键；`teleop_keyboard` 默认线速度只有 0.15 m/s 左右，
> 按 `w` 后要持续按住/反复按才会明显移动。

**核实话题（终端 C）：**

```bash
ros2 topic list -t                 # 看全部话题+类型
ros2 topic type /cmd_vel           # 应为 geometry_msgs/msg/TwistStamped（Jazzy 变更点！）
ros2 topic hz /odom                # 应在出数
ros2 topic hz /camera/image_raw    # 应在出数（很慢，见下）
ros2 topic echo /odom --field pose.pose.position --once
```

**实测参考值（我在这台机器上量到的）**：

| 话题 | 类型 | 实测频率 |
| --- | --- | --- |
| `/clock` | `rosgraph_msgs/msg/Clock` | 54–62 Hz |
| `/odom` | `nav_msgs/msg/Odometry` | **2.8 Hz** |
| `/scan` | `sensor_msgs/msg/LaserScan` | **0.6 Hz** |
| `/camera/image_raw` | `sensor_msgs/msg/Image`（640×480, `rgb8`） | **0.7–1.0 Hz** |
| `/imu` | `sensor_msgs/msg/Imu` | 13–14 Hz |
| `/joint_states` | `sensor_msgs/msg/JointState` | 44–56 Hz |
| `/tf` | `tf2_msgs/msg/TFMessage` | 4.6 Hz |

**⚠️ 频率偏低是正常的**，软件渲染拖慢了 Gazebo 的物理与传感器更新。
如果 `ros2 topic hz` 半天不出数，说明采集窗口不够，让它多跑 10 秒。

**你要回答的**：Gazebo 产生了什么数据、RViz 显示了什么数据 —— 见文末「三个必答题」。

## 4. 任务 3：坐标系树与两组 tf 查询

```bash
mkdir -p ~/task1_ws/docs/evidence && cd ~/task1_ws/docs/evidence

ros2 run tf2_tools view_frames
# 等 5 秒，生成 frames_<时间>.pdf 和 frames_<时间>.gv

ros2 run tf2_ros tf2_echo odom base_footprint          # 按 Ctrl+C 停
ros2 run tf2_ros tf2_echo base_link camera_rgb_frame   # 按 Ctrl+C 停
```

**怎么判断哪段是动态、哪段是静态 —— 看时间戳，这是最硬的判据：**

| 关系 | 静止时的输出 | 时间戳 | 结论 |
| --- | --- | --- | --- |
| `odom → base_footprint` | 平移 `[0,0,0]` | **在推进**（如 9.86 → 9.92 → 10.00），速率 53 Hz | **动态** |
| `base_link → camera_rgb_frame` | 平移 `[0.076, 0, 0.093]` 恒定 | **恒为 0.0** | **静态** |

**再做一次对比实验（关键）**：让小车动起来（终端 B 按 `w`），**同时**观察
`tf2_echo odom base_footprint` —— 你会发现平移值开始变化（x 逐渐增大），
而 `tf2_echo base_link camera_rgb_frame` 的 `[0.076, 0, 0.093]` **一点都不变**。

**树的来源**（我查证过）：

- `/tf` 有 2 个发布者：`ros_gz_bridge`（发布 `odom→base_footprint` 和两个轮子）+ `robot_state_publisher`（轮子关节）
- `/tf_static` 只有 1 个发布者：`robot_state_publisher`（URDF 里固定的 link，如相机、雷达、imu）

## 5. 任务 4：RViz 里检查 Status

RViz 已经加载了我写好的 `basic.rviz`，里面配了：

| Display | 话题 | 类型 |
| --- | --- | --- |
| Grid | — | 参考网格 |
| RobotModel | `/robot_description` | 小车模型 |
| TF | `/tf` + `/tf_static` | 坐标轴/箭头 |
| LaserScan | `/scan` | 红色点 |
| Image | `/camera/image_raw` | 相机画面 |

**你要做的检查**：

1. 左侧 `Displays` 面板，把每项**展开**，看它的 `Status` 那一行
2. `Global Options → Fixed Frame` 应为 **`odom`**
3. 3D 视图里用鼠标左键拖拽旋转、滚轮缩放，应当能看到网格和激光点

**已知会出现的提示（我实测到的）**：

> `[rviz2]: Message Filter dropping message: frame 'base_scan' at time 0.002 for reason
> 'the timestamp on the message is earlier than all the data in the transform cache'`

- **出现次数**：我观察只出现 **1 次**，在刚启动时
- **原因**：LaserScan 的时间戳比 TF 缓存里最早的时间还早（仿真刚起步时 TF 缓存还没建立），
  属于启动瞬态；`/scan` 只有 0.6 Hz，跟不上 TF 缓存滚动
- **判定**：不是配置错误。若状态里 TF/Image 为 OK、LaserScan 偶发 Warning，属可接受
- **若持续报**：让 Gazebo 多跑一会儿再回看，或把 Fixed Frame 临时改成 `base_scan` 对比

**把 Status 面板拍下来**：这是任务书要求的证据，截图时记得标注显示项和话题。

## 9. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `KeyError: 'TURTLEBOT3_MODEL'` | 上游 spawn 启动文件在解析期就读这个变量 | 确认已 `export TURTLEBOT3_MODEL=waffle_pi`；我的 Launch 里已做兜底 |
| Gazebo 半天不出画面 | 软件渲染（`VMware: No 3D enabled`） | 耐心等 1–3 分钟，别开全屏 |
| `ros2 topic hz` 不出数 | 传感器只有 0.6–3 Hz | 多等一会儿 |
| RViz 里什么都看不到 | 仿真是慢的，或 Fixed Frame 不对 | 确认 Fixed Frame = `odom`；确认仿真已在跑 |
| 回放时 RViz 空白 | 忘了 `--clock` 或没用 `use_sim_time` | 见 7.7 |
| `/cmd_vel` 发不进去 | 发成了旧版 `Twist` | 本模型是 **`TwistStamped`**，要带 `header` |
| 想手动发速度验证 | —— | `ros2 topic pub /cmd_vel geometry_msgs/msg/TwistStamped "{header: {frame_id: base_link}, twist: {linear: {x: 0.15}}}" -r 10` |

## 11. 三个必答题（提示，请用你自己的话写）

**1. Gazebo、RViz 和 rqt 在本项目中分别负责什么？**

> Gazebo 是**物理与传感器仿真器**，产生 `/odom` `/scan` `/camera/image_raw` `/imu` `/tf` 这些**数据源**；
> RViz 是**数据可视化**，把 TF、激光、图像按配置好的布局画出来，是"看结果"的地方；
> rqt 是**调试与系统观察**工具集，Node Graph 看节点/话题连接关系，Image View 快速验证图像流。
> 一句话：Gazebo 产数据，RViz 看数据，rqt 查关系。

**2. `odom → base_footprint` 与 `base_link → camera_rgb_frame` 为什么分别属于动态和静态关系？**

> 前者由轮子里程计推算，小车一动位姿就变，是**随时间变化的量**，必须每帧广播（53 Hz），时间戳持续推进；
> 后者是 URDF 里相机相对车体的**安装位置**，机械上固定不变（本机为 `[0.076, 0, 0.093]`），
> 只需发一次，走 `/tf_static` 且时间戳恒为 0。

**3. rosbag 能回放什么，不能直接恢复什么？**

> 能回放：当时**发布过的 ROS 消息流** —— 图像、`/odom`、`/tf`、`/tf_static` 都能重新发布，
> 所以只用 RViz 就能重现画面和坐标变换。
> 不能恢复：**Gazebo 的物理世界状态**（模型位姿、碰撞、正在施加的力），
> 也不能恢复没有录制的话题或服务调用；`/tf_static` 还必须在录制开始前就先启动录制器，否则抓不到。
